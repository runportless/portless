# Initial implementation boundary

This repository is a runnable vertical implementation of the product direction, not a claim that every public-release hardening milestone is finished.

## Complete in this slice

- Reusable logical projects, named environments, and a top-level environment HTTP API.
- Static, bounded, plugin-driven single- and multi-checkout framework discovery for Spring Boot, NestJS, Express, Fastify, Next.js, Go HTTP/RPC services, and FastAPI; evidence-ranked HTTP readiness discovery for literal framework routes and configuration with TCP fallback on dynamic or ambiguous evidence; atomic incremental source addition, cross-source dependency compilation, generated declaration export, and fail-closed name conflict responses.
- A separate managed-resource registry with plugin-owned detection, version and client port resolution, declarative container plans, readiness, persistent named volumes, generated credentials, and redacted process bindings. PostgreSQL, Valkey, MySQL, and NATS are built in. Generic or missing resource hosts are deterministically consumer-scoped on the first scan, while a shared specific single-label host explicitly converges consumers on one managed service; a fixture plugin verifies that the shared engine and runtime require no resource-specific branch.
- Environment cloning, per-checkout selection, per-environment Git-worktree paths, and independently mutable component providers. Active provider changes are durable service-scoped operations with non-mutating remote preflight, runtime-preserving persistence, stable edge listeners, and rollback to the previous provider; unrelated services are not restarted.
- Local process, plugin-backed managed Docker/Podman resource, remote HTTP(S), and deterministic HTTP mock providers. Remote providers include classification, health checks, and local read-only enforcement; mock providers include private runtime listeners, method/path/query matching, fixed responses and delays, preview, recording/OpenAPI import, and service-scoped hot handoff.
- Singleton daemon composition and control with separate API contract, authenticated client, HTTP server, lifecycle, instance-record, relay, relay-installation, and standard-library-only installation boundaries. Architecture tests enforce their dependency direction; lightweight authenticated identity/status polling is separated from explicit bounded-concurrency runtime-handoff audits, while guarded CLI/UI restart repeats a fresh audit and fails closed. Normal CLI, browser, MCP, and executable-change triggers coalesce through one receipt-based `exec` handoff with cancelled streaming contexts, bounded drain/cleanup, a fixed five-second ready deadline, and last-restart timing diagnostics. Automatic replacement of handoff-ready outdated builds, startup runtime reconciliation, a private instance record, read-only doctor diagnostics, Cobra command tree with generated shell completion, CLI token, restart-safe browser claim/session/CSRF flow, and the embedded UI remain in place.
- Idempotent macOS launchd or systemd Linux first-run setup plus explicit relay install, status, restart, repair, and uninstall commands for system-resolvable port-80 `.localhost` URLs and scoped `.portless.test` TCP DNS, with a root-owned ownership receipt and machine-wide lifecycle lock. Install and repair replace and directory-sync service artifacts transactionally, restore the prior service state when activation or end-to-end readiness fails, reject ambiguous service-manager results, and use the receipt as the exact ownership manifest for macOS loopback aliases. The relay verifies that its runtime UID, GID, private sockets, and loopback manifest exactly match the receipt before binding; inspection also detects deterministic service or resolver content drift. Forced cleanup never removes aliases without a valid receipt and reports any residual pool for explicit operator recovery. The relay binds only its HTTP and DNS loopback addresses as root, drops privileges, synthesizes fixed loopback answers for the special-use localhost zone, and forwards HTTP traffic and dynamic endpoint DNS to separate private per-user Unix sockets.
- Persistent authenticated process supervisors and a generic, label-owned Docker Engine/Podman lifecycle for validated resource plans, including daemon-crash adoption, automatic and explicit runtime selection, per-service start/stop/restart operations, plan-identity verification, and restart accounting. From a discovered service directory, `portless up` can launch Node/NestJS or Spring Boot under the same supervisor with a private Node inspector or JDWP endpoint; debug modes are additive and survive daemon handoff without transferring process ownership to the IDE.
- Stable application ingress, durable collision-free TCP loopback/DNS allocations, effective-connection inspection, source-aware internal edge proxies, and a unified HTTP/TCP exchange API. TCP inspection emits bounded Redis, PostgreSQL, MySQL, and NATS operations when a managed resource declares one of those protocols, and explicit opaque, encrypted, unsupported, malformed, or limited session fallbacks otherwise; inspection cannot block forwarded traffic. Successful recognized PostgreSQL/Redis driver and pool housekeeping remains in raw exchanges and recordings but is background in standalone traces and topology, while failures and faulted operations remain foreground. Passive W3C/OpenTelemetry, B3 single/multi-header, and Datadog trace-context projection retain normalized identifiers and explicit correlation confidence. Trace and raw-exchange inspection, lossless repeated request/response headers, bounded payload prefixes, bounded named recordings with opt-in payload persistence, and scoped named faults share the same traffic path. Mock-served exchanges retain their provider, profile, and route attribution.
- Structured process and container logs across generations, merged service views, time and count filters, 10-generation retention, and a 16 MiB cap per generation stream.
- Human-first CLI inspection for projects, services, effective connections, timelines, recordings, and faults, including each service's effective readiness kind, HTTP path, timeout, and interval; every command also supports machine-readable `--json` output. `portless down --all` performs a checkout-independent, failure-aggregating machine-wide shutdown, with explicit confirmation before bulk volume removal. A guarded `portless reset` previews and, with `--yes`, clears stopped application state and installation-owned runtime resources while preserving Portless installation and preference state. `--force --yes` also purges active, unknown, or format-incompatible environments after authenticating their supervisors and installation-labeled container resources; daemon identity and reset planning remain available through normalized runtime ownership when versioned topology decoding fails. A separate preview-first `portless uninstall` performs failure-barriered full removal of those runtimes, the owned HTTP/DNS relay and resolver, daemon/data state, and a safely classified CLI launcher without deleting source builds.
- Context-aware shell completion for environment selectors and daemon-owned names. Completion is quiet and never starts or replaces the daemon.
- A top-level, CLI-consumed `portless-mcp` stdio server with 15 read-only tools by default, immutable workspace/pinned/installation scope, safe DTO mapping, bounded results and concurrency, MCP actor attribution, and separately gated sensitive-traffic, lifecycle, and bounded recording/fault capabilities. It does not expose daemon/relay administration, reset, uninstall, volume deletion, command execution, arbitrary files, or arbitrary URLs.
- Project/environment UI, provider and source configuration with editable or native-picker checkout paths, mock profile/route editing and request preview, topology, service detail/configuration/logs, trace-first traffic waterfalls with pagination, buffered pause/resume, scoped live-buffer clearing, and redacted credential-bearing headers, recording, fault, timeline, command-palette views, and a Settings MCP client-configuration generator with explicit immutable scope and capability selection.
- A greenfield SQLite schema with durable logical project, environment, mock profile/route, daemon ownership, service/supervisor runtime, dependency-listener, operation, timeline, recording, fault, and recorded-traffic state. Persisted discovery models carry an explicit format version and reject incompatible pre-resource state with reset-and-rediscover guidance.
- Unit and integration coverage for the principal lifecycle, routing, and experiment paths.

## Deliberately deferred from a hardened public release

- Zero-gap daemon upgrades and automatic rollback. A safe handoff keeps application processes and containers alive and restores their ingress and dependency listeners on the same ports; the replacement serves durable endpoint DNS during reconciliation and honors each service's bounded health window before claiming it, but requests can briefly fail while the old daemon releases listeners and the new daemon verifies ownership. A runtime proven absent from authenticated durable process evidence or exact container ownership becomes stopped and the next `portless up` recreates it. If a supervisor, process group, container label, runtime, or saved listener remains ambiguous, Portless marks the service `unknown` and refuses to launch a duplicate; that recovery remains an explicit operator action.
- Editable discovery overrides beyond source paths, change previews, and declaration import.
- Installation and sandboxing of third-party discovery or resource plugins. Version 1 registers trusted in-process plugins at build time; any external plugin mechanism requires a separate versioned subprocess and permission design.
- Push-based log SSE and byte-level rotation within an active generation. The CLI follows retained structured logs by bounded polling; generation count and file size are capped.
- HAR export, globally configurable capture limits, framework-specific trace propagation, and traffic-list virtualization. The recorder remains JSON-only; live authenticated exchange detail includes bounded HTTP body and decoded TCP message prefixes, while durable recordings capture payloads only when a recording explicitly opts in with its own bounded limit.
- Stateful, scripted, templated, passthrough, WebSocket, gRPC, TCP, and binary mock behavior. The initial mock provider deliberately returns fixed HTTP responses from a deterministic matcher and returns `501` when no route matches.
- TCP-specific reset/drop-after-byte effects. TCP edges support delay/rejection through the shared fault model; advanced stream effects remain.
- Operation cancellation, bounded-parallel graph execution, long-lived port lease recovery, and resource-cap enforcement under load.
- Windows support, nerdctl adapters, packaging, notarization, upgrade rollback tooling, SBOM generation, and release soak tests.

These items should be treated as release gates, not hidden behavior. The architecture keeps them behind store, runtime, proxy, and API boundaries so they can be added without changing the public naming model or user workflow.
